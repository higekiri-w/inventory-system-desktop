### 起動の道

- `tauri-driver`: `cargo install tauri-driver --locked --version 2.1.0`（crates.io の 2.1.0 は 2026-09-26 公開で yanked でない、MSRV 1.90。<https://crates.io/api/v1/crates/tauri-driver>、2026-11-23 に取得。2.1.0 の変更は edition 2024 と MSRV だけ、<https://raw.githubusercontent.com/tauri-apps/tauri/dev/crates/tauri-driver/CHANGELOG.md>）。公式の手順は版なしの `cargo install tauri-driver --locked`（<https://v2.tauri.app/develop/tests/webdriver/manual-setup/>）なので、`--version` で pin する。新しい 3.0.0-alpha は使わない。
- `msedgedriver`: WebView2 の Runtime の版に合わせる。Microsoft は「Make sure the version of Microsoft Edge WebDriver matches the version of the WebView2 Runtime that your app uses.」（<https://learn.microsoft.com/en-us/microsoft-edge/webview2/how-to/webdriver>）、Edge との組では「The first three parts of the four-part version number must match」（<https://learn.microsoft.com/en-us/microsoft-edge/webdriver/>）。Runtime の版は registry の `pv`（`HKLM\SOFTWARE\WOW6432Node\Microsoft\EdgeUpdate\Clients\{F3017226-FE2A-4295-8BDF-00C3A9A7E4C5}`、無ければ `HKCU\Software\Microsoft\EdgeUpdate\Clients\{同じ GUID}`。<https://learn.microsoft.com/en-us/microsoft-edge/webview2/concepts/distribution>）。
  - 入れ方: workflow の pwsh の step が `pv` を読み、`https://msedgedriver.microsoft.com/<pv>/edgedriver_win64.zip` を落として展開し、`Get-AuthenticodeSignature` で展開した `msedgedriver.exe` の `Status -eq 'Valid'` と、署名者の名 `$sig.SignerCertificate.GetNameInfo([System.Security.Cryptography.X509Certificates.X509NameType]::SimpleName, $false)`（証明書の subject の CN）が `-ceq 'Microsoft Corporation'`（完全一致）であることを確かめてから、`tauri-driver --native-driver <その exe>` に渡す（<https://learn.microsoft.com/en-us/dotnet/api/system.management.automation.signature.signercertificate>、<https://learn.microsoft.com/en-us/dotnet/api/system.security.cryptography.x509certificates.x509certificate2.getnameinfo>）。`pv` が無い・download が落ちる・署名が合わなければ step が赤。読んだ `pv`・`msedgedriver --version`・署名者の名を log に出す。
  - 版の固定: driver の版は pin せず、毎回 `pv` に合わせる（Runtime は image と一緒に変わるので、固定すると合わなくなる。合わないときの症状は「hanging while trying to connect」、manual-setup の頁）。
  - 棄却: (a) Tauri の文書の `cargo install --git https://github.com/chippers/msedgedriver-tool`（version も commit も pin しない git の install。中身は同じ registry の読みと同じ URL の download で、`src/main.rs` の `driver_url` が `https://msedgedriver.microsoft.com/{version}/edgedriver_{platform}.zip`、2026-11-23 に読んだ）。(b) image に入っている `EDGEWEBDRIVER`（`C:\SeleniumWebDrivers\EdgeDriver`、Edge Driver 157.0.4341.60。<https://raw.githubusercontent.com/actions/runner-images/main/images/windows/Windows2025-VS2026-Readme.md>、Image Version 20261116.315.1）。Edge の版には合うが、WebView2 の Runtime の版は readme に無く、合う保証が無い。
- build: release（`npm run tauri -- build --no-bundle`）。理由: (1) debug の build は `tauri.conf.json` の `devUrl`（`http://localhost:1420`）を読み、vite の dev server が要る。`tauri build` は `beforeBuildCommand`（`npm run build`）で frontend を build して埋め込む。(2) debug にだけある code（`src-tauri/src/lib.rs:1426-1445` の bindings の書出しと起動の失敗の模擬の plugin）を通さず、配る exe と同じ構成（`custom-protocol` あり）で確かめる。`tauri build --debug` は (1) を満たすが (2) を満たさない。frontend の build は要る（`npm ci` は `.npmrc` の `ignore-scripts=true` のまま。`@tauri-apps/cli-win32-x64-msvc` 2.11.1 は `package-lock.json:3795` にある）。
