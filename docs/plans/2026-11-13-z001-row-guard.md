## Goal

Goal Invariant:

### 最小完了条件

- `get_completed_daily_report_aggregate` の `summary_imports` の各取込みの行が、その親の id を持つ Z001 の行の全部（行の `sort_order ASC, id ASC` の順）になり、行の query の並びが親の query の並びと一致するかに依らない。
- 手順 1 の親に無い id の行（今の到達できる状態では生じない）は、どの取込みにも入らず、後の親の行を遮らない（24 §14.21a 手順 2 と同じ扱い）。
- 今の到達できる全ての状態で、日次売上の画面・日次 CSV・日報の紙に出る値と並びが変わらない（既存の test が全部 green のまま）。

### 失敗定義

- 行の query の ORDER BY の親の部分（`i.imported_at ASC, i.id ASC`）を変えると、ある親の行が空になる・別の親に入る（今の実装の失敗。下の「調べ」の M1）。
- 親に無い id の行が 1 つあると、それより後の親の行が全部空になる（今の実装の失敗。下の「調べ」の M3）。
- 取込みの中の行の並び（`sort_order ASC, id ASC`）、行の無い親の空の取込み、取込みの件数（= `source_import_count`）、取込みの並び（`imported_at ASC, id ASC`）のどれかが変わる。
- 新しい error・文言・DTO の field が増える。

### 非目的

- 取込みの間の Z001 の表の見せ方（backlog「日計（Z001）の表の見せ方をデザイン刷新の要求仕様にする」）。
- 支払の行（手順 3）・部門の行（手順 4）の読取り。支払の行は BIZ-05 の `apply_sheet_rule` が `import_ids` の位置で引いて親に無い行を読まず、もう並びに依らない（下の「調べ」）。部門の行は親を跨いで集約し、取込みごとに分けない。
- `get_daily_report_sheet_lines`（§14.21a）。行を親の id の集合で絞るだけで、もう並びに依らない。
- 親の読取りと行の読取りを 1 つの transaction に入れること（今は同じ接続の Mutex の中で、間に書込みが入らない。下の「前提」）。
- 行の query の ORDER BY の親の部分を消すこと（下の「この変更で不要になるもの」で残す理由）。

Priority: `Goal Invariant > Acceptance Criteria > supporting evidence`。AC や証跡作業が Goal Invariant を前進させない場合は、Goal を置き換えず簡略化・defer・削除する。

## 案の比較

- **(b) 採る: 行を親 id で集め、親の並びで引く（前提ごと消す）。**
  - 形: 行の query の結果を、親 id を key にした `HashMap` に行の順のまま push し、手順 1 の親の並びで各親の行を `remove` で取り出す（無ければ空）。取込みの中の行の並びは、同じ親の行が SQL の `l.sort_order ASC, l.id ASC` の順で push されるので変わらない。親に無い id の行は map に残って読まれない（§14.21a 手順 2・`apply_sheet_rule` と同じ扱い）。
  - 理由: 前提（2 つの query の並びの一致）そのものを無くす。guard を足すより code が短く（`peekable`・`next_if`・`from_fn` が消え、`HashMap` の entry と remove になる）、確かめる場合が減る（並びがずれたときの挙動を考えなくてよい）。標準ライブラリだけで、依存・抽象・設定を足さない（D-147）。同じ日の読取りの隣（支払の `apply_sheet_rule`、§14.21a）がもう親 id で引いていて、同じ扱いにそろう。
  - 危険: 親に無い id の行を黙って読まないことになる。今の到達できる状態では生じず、生じる経路（2 つの読取りの間の確定）では読まないことが正しい（§14.21a 手順 2 と同じ理由。確定の前に読んだ親の件数・gross / net と行がずれない）。M3 の mutant は等価になり（下の Test Plan）、取り消した親の行を読まないことは行の query の `status = 'completed'` と、親の query の条件（`..._skip_rolled_back_parent` が守る）の 2 か所で保つ。
- **(a) 見送る: 取り分けの後に残りの行が無いことを確かめ、あれば内部の error にする。**
  - 遮りの失敗（M3）は error になって見えるが、ORDER BY のずれ（M1）では先頭の行が合わない親から全部が残りになり、その日の日次売上の画面全体が「データベースエラーが発生しました。もう一度お試しください」（24 §14.21 手順 7 の既存の文、CMD-ERR-D2）で開けなくなる。正しく読める data を error にする。
  - 親に無い id の行（2 つの読取りの間の確定）も error になり、§14.21a と食い違う（紙は読まずに出し、画面は error）。
  - 前提を残したまま検査を足す形で、AGENTS.md「継ぎ足さない」に当たる。code は今の取り分けに検査が加わる分だけ長い。
- **(c) 見送る: 親と行を 1 つの query（LEFT JOIN）で読み、親の行の切れ目で分ける。** 行の無い親を LEFT JOIN で残せるが、gross / net の加算の順（手順 1）・`source_import_count` のための親の読取りを別に残すか、1 つの query の結果から親を重複なしに取り出す処理が要る。並びに依る取り分けがそのまま残り（行の切れ目の判定）、(b) より大きい。
- **(c') 見送る: 2 つの読取りを 1 つの transaction に入れる。** 親に無い id の行の経路だけを閉じ、ORDER BY のずれ（M1）の失敗は残る。今は Mutex の中で書込みが入らず、効く経路が無い。
