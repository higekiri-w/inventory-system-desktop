## Failure Modes

- drive 文字の変化で、レジの SD・目印の無い媒体・別の PC で用意した媒体に書く。探した後に抜かれ、同じ文字に割り当たった別の媒体に書く。新しい版の目印を作り直す。
- 写した file を読み戻さずに成功とする。照合の失敗の file が正式名で残る。壊れた・空の・このアプリのものでない写す元を写す。
- 媒体の上の掃除が、今写した file・目印・規約外の file を消す。久しぶりに差した媒体の古い控えを日付で一度に消す。
- 状態の file が壊れたときに黙って `NotPrepared` になる。媒体が見えないときに `last_success` を消す・変える。作り直し・やめるの途中の失敗で記録や再試行の入口を失う。
- 成功の記録を置き換えた後の sync の失敗で、card が成功の日時と失敗の文を並べる（design の packet の closeout の申し送り (b)）。
- 用意済みの媒体が差してあるのに「USB メモリが差してあるか確かめてください」を出す（申し送り (a)）。
- 共通の確認が復元の間（控えの確かめの開始から）に写す・掃除する。用意・作り直しの実行中に画面を離れて戻ると、その掃除の最中に控えの確かめ・復元へ進める（Final Review 810 の P2）。lock を持った thread の panic の後、確認・用意・作り直し・やめるが再起動まで全部止まる。古い世代の結果で status を invalidate する。媒体が抜けているだけで毎分 toast を出す。抜き差しの後に差してある媒体の表示が変わらない。
- 媒体の `InventoryBackup` の reparse point を追って、PC の中や別の媒体に書く・消す。目印の作業名（`offsite-medium.json.tmp`）の link を辿って媒体の外の file を目印の JSON で書き換える・作る（Final Review 810 の P2）。規約の名前の link を写しに数え、本物の控えを余計に消す。規約外の多バイトの名前で媒体の写しの並びが panic する。command を main thread で動かして写しの間に画面が固まる。写す間 DB の Mutex を持つ。
- ホームが用意の前・やめた後に知らせる。3 日の境界がずれる。原因が PC の中の backup・記録・空きなのに USB の文を出す。
- 選んだ file が復元の流れに入らない・別の path で戻す。作成日時が取れない file で日時を作り出す。アプリの今の DB を選んだときに DB を失う。
- PC の中の保存先が媒体の `InventoryBackup` と同じ folder のときに、用意する・保存する・黙って `UpToDate` を返す（J1）。junction・symbolic link・drive 文字の違いで同じ folder を見落とす。`InventoryBackup` の中の folder や媒体の root まで止める。確かめの前に保存する・確かめと違う値を保存する。

## Test Matrix

- 既存の test を回帰の証跡に挙げる前に `rg` で実在を確かめる（下の Adjacent Pattern Audit の既存は 2026-11-02 に main 取込み後の現物で照合した名前。新設予定の test は実在の証拠ではない）。
- 媒体の発見は root の列を受ける内部関数に一時 directory を渡して通し、production と test で別の判定を作らない（71 §71.11.3）。drive の種類の判定（`GetDriveTypeW`）は L3-b1〜L3-b3 で確かめる。
- 写しの失敗の注入は共有済みの `RestoreFileOps` の sync・公開・読取り・書込み・置換えを使う。原本の退避（71 §71.11.5a 手順 5）と作業名への写し（§71.11.4 手順 4d）には、同じ `create_new` の copy を追加して注入する。操作の順を記録し、`sync_all` や親 directory の sync を省くと red にする。排他の並行 test は §71.11.4 の注入境界を使い、root・時刻・操作を受ける、本番と同じ mutex を取る入口を通す。各 thread に渡す注入の型は channel / barrier で copy を待たせ、取得前後の通知と file 操作を記録する（既存 trait 全体に `Send + Sync` を足す必要はなく、型を各 thread の中で作れる）。取得を試みた後、待機中に本体へ入らないこと・解放後に完了することを期限付きで確かめ、sleep だけで順を仮定しない。
- 時刻と今日の日付は注入できる形にする（3 日の境界・同じ秒の退避名の case のため）。
- 原因の文の行（UI-11b-D14・UI-00-D12）の mock の status は、どれも `prepared = true`・`stale = true` を前提にする（原因の文は `stale = true` のときだけ出る。design の packet の closeout の申し送り (c)）。`stale = false` と用意の前の行は別に置く。
- mock の日数・札は設計の例（3 日・控え 1）と違う値（5 日・控え 2）を使い、表示が mock から来たことを確かめる。

## Negative Paths

- missing input: 空の `selected_path` は `validation`。PC の中に backup が無ければ `NoLocalBackup`。file picker の cancel は何もしない。

- unknown reference: 目印の `medium_id` が状態に無い媒体には書かない。file の入口でアプリの今の DB を選んだとき（UI-11b-D15 隣接の行）。
