## Risk

Risk: R3

Reason:
POS CSV（Z004）の取込みを SD の一括の操作に足し、在庫の求め直しに繋がる operator の業務の流れと、Tauri command の DTO（`RegisterSdBulkSource`・`RegisterSdBulkOutcomeDto`・`DailyReportSdScan`）を変える（DEV_WORKFLOW の Risk Tiers の R3）。R4 でない理由: 既存の記録を書き換える・消す経路を足さず（Z004 の確定と取消は 32 の今の関数のまま、取消は D-118 の per-import の取消）、migration・restore・secret に触れず、SD へ書かない（BIZ-08-D10）。

## Goal

Goal Invariant:

### 最小完了条件

- 店の人が「SD から読む」の後に「まとめて取り込む」を 1 回押すと、日報に続いて SD の Z004 が精算回数の古い順に取り込まれ、在庫連動の商品の在庫が動き、Z004 の項目ごとの結果（取り込みました・一部を取り込みました・取り込みませんでした）と要再確認の商品が日本語の文で出る（37 §37.10 手順 1 (b)・3、55 UI-07-D17）。Z004 の file を手で探して選ぶ操作が日々の締めから無くなる。
- 一括は、商品の最初の登録日とそれより前の精算日の Z004 と、同じ hash を一度でも取り込んだ Z004（取り消した分を含む）を取り込まず、結果にも数にも出さない（Design Readiness の O1、TD-922・TD-924・TD-925）。Z004 タブで選んだ file は今どおり取り込める。

### 失敗定義

- 運用開始の前（登録日を含む）の Z004 を一括で取り込む（在庫が初期在庫から二重に引かれる）、登録日の翌日以後の Z004 を飛ばす、取り消した Z004 を一括が入れ直す、暦に無い精算日の file を黙って消す、Z004 タブの取込みを止める。
- 写しの無い Z004 を確定する、同じ精算の Z004 を二重に入れる、32 の表の拒否を飛ばさずに止まる、確定の段の失敗の後も続ける。
- 読めなかった Z004 を結果で名指ししない、一部だけ入った取込みを「取り込みました」と出す。
- PLU の占有の照合（PR #307 の手順 10・§45.6a 手順 2a）の結果が変わる。
- 実の Z004・POS file・DB を fixture にする。

### 非目的

- Z004 タブ（file を選ぶ経路）の振舞い（O1 の規則も当てない。TD-922）。
- 32 の検査・確定・取消の規則、IO-02 の parse、IO-09 の列挙の規則、D-149 の片付け（Z004 は組に付けて移すまま）。
- EJ の閲覧（(A-2)、関門 19）、PLU の照合の規則（PR #307）。
