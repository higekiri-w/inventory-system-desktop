# 日報・月次の画面の導入前受入の手順（開発用の Windows、管理者向け）

> **対象**: アプリを管理する人。店の利用者の操作にしない。店の PC では行わない。
> **いつ使うか**: 店へ入れる版の MSI（[initial-load-runbook.md](initial-load-runbook.md) の流れ 2 と同じ版）ができた後、店の PC への初期投入（同じ手順書の流れ 3）の前に。完了の画面を離れた後の取消の入口の lane（以下 A）と、月次の画面に月の中の取り込んだ日を出す lane（以下 B）が merge された版で行う（[Plans](Plans.md#導入の前の関門) の導入の前の関門の 12）。
> **引く正本**: 受入の項目・合格基準・判定は [56](function-design/56-ui-daily-sales.md) UI-09a-D13 と [57](function-design/57-ui-monthly-sales.md) UI-09b-D9 の受入の段、SD の一覧と「場所を選ぶ」は [55](function-design/55-ui-csv-import.md) UI-07-D15、窓（今日から 30 日前まで）は [37](function-design/37-biz-daily-report-import-service.md) §37.9、写しの folder の選び方（`resolve_register_sd_root`）と取込みのときの写しは [29](function-design/29-io-daily-report-parser.md) IO-09・IO-10、復元は [68](function-design/68-ui-backup-restore.md) §68.4、backup を SD の上に書かないことと別の PC に店のデータを置く間の扱いは [71](function-design/71-mnt-backup.md) MNT-01-D10・§71.13。owner の決定は repo 外の回答台帳 TD-570（関門 12）・TD-578（場と時期・店の事実・前提の lane・FAIL の扱い）・TD-580（綴りの紙の運び方）・TD-650（手順 5 の日の紙も借り、値を比べる相手を借りた紙にそろえる）。本書は正本の契約を引いて手順を並べ、正本に無い所は安全側に倒した管理者の判断を足す（紙を借りる日を写しを取った日に近くすること、同じ日に予行演習と続けるときの順）。食い違えば正本が正しい。
> **この受入が置き換えないもの**: 日報の紙と月の売上の紙のどちらも置き換えない（57 UI-09b-D9）。日報の紙の切替えの前の照合（56 UI-09a-D19 の (2)、TD-560）は運用開始の後に別に行う。

## 店のデータの置き場と渡し方

店の実データとして扱うものは次の 3 つで、置き場の決まり方が違う。どれも、repo の checkout（ignored の `.local/` を含む）と cloud の同期の folder に置かず、AI の agent に渡さない。

- **管理者が作る SD の写し**: レジの SD の `CASIO` の下の全 file。売上の Z 帳票と EJ を持つ `XZ`・`XZ_BKUP` のほか、`BACKUP` の `.000`（スマホへ送れなかった精算データの控えで、1 本が 1 回の精算の束）と `AUTOPGM` のレジの設定も入る（[project-memory](project-memory.md) の「レジ・レジスターツール」の SD の配置の行と、SD の `BACKUP` と `AUTOPGM` の行）。アプリが読まない file も同じ扱いにする。置いてよい所は 2 つだけで、管理者の USB メモリの、root でない日付の付いた folder（その USB メモリは店の PC と開発用の Windows でだけ開き、受入の間は管理者が手元に保管する）と、開発用の Windows の、drive の直下でない日付の付いた folder。
  - 開発用の Windows の folder は、置く前に、repo の checkout の中（ignored の `.local/` も不可）でも `%OneDrive%` の下でもないことを確かめる（デスクトップ・ドキュメントは同期の下でありうる）。
  - どちらの置き場も、アプリの folder（`%APPDATA%`・`%LOCALAPPDATA%` の `com.inventory-system.desktop`）と、その別名の folder（下の「準備」の 2 で開発の data folder を退避した先と、下の「アプリが作る物」の、受入の data folder を別名で残した先）の中に作らない。中に置くと、準備の退避や片付けで写しが一緒に動く。
  - drive の直下・USB メモリの root に `CASIO` を置かない。開発用の Windows では自動の探索がその USB メモリを SD と見なし（29 IO-09 の手順 1）、店の PC で SD と一緒に差すと SD が 2 枚と数えられ（37 §37.9 の手順 1）、その drive への backup も止まる（71 MNT-01-D10）。
- **アプリが作る物**: 受入の data folder（取り込んだ記録の DB・アプリが残す SD の写し〈IO-10〉・backup）と WebView の保存の folder。置き場は 2 つだけで、管理者は場所を選ばない。アプリの固定の場所（受入の間の `%APPDATA%\com.inventory-system.desktop` と `%LOCALAPPDATA%\com.inventory-system.desktop`。下の「準備」の 2・3）と、同じ `%APPDATA%`・`%LOCALAPPDATA%` の中で名前を変えて残す別名の folder。別名の folder ができるのは、終わった後の片付け（下の「終わった後」の 1）と、受入の data folder が壊れたときの保全（下の「受入の data folder が壊れたとき」）の 2 つだけ。backup の保存先を受入の data folder の外へ変えず（手順 6 の 1）、この場所から他（SD の写しの置き場・USB メモリ・repo・cloud を含む）へ写さない・移さない。
- **借りた綴りの紙**: 紙かそのコピーを店から借りて開発用の Windows の前で並べ、返す（TD-580・TD-650）。借りている間は USB メモリと同じく管理者が手元に保管し、コピー・スキャン・写真を作らない。

渡し方の規則:

- AI の agent（Claude・Codex）への発注・報告・handoff に、写し・受入の data folder・backup の path や店の値を書かない。agent に読ませる作業をしない（agent は開発用の Windows の file を読めるので、場所でなく渡し方で守る）。owner への報告は TD 番号で引く。
- 画面の値を別の画面や紙へ運ぶために、画面の写し・写真・書き写し（紙・file とも）を使わない。値を比べるのは画面と借りた綴りの紙の間だけ（TD-650）。
- 受入の間は、`日次売上` の `CSV 出力`・`日報を印刷` と、`月次売上` の `CSV 出力` を押さない（上の置き場の外に、店の売上の file・紙ができうる）。
- repo に入れないもの: 店の売上の値（金額・件数）、SD の file と写し、綴りの紙・そのコピー・画面の写し、実の JAN・商品名・店の file 名の実例。本書は金額を書かず、file 名は形（`Z001_…` の類）だけで書く。

## 写しを取る（訪店の時）

1. 店の PC で、レジの SD の `CASIO` の folder を丸ごと（中の `SR500_550_4000` の `XZ` と `XZ_BKUP` ごと）、管理者の USB メモリの root でない日付の付いた folder の中へ写し、`<日付の folder>\CASIO\SR500_550_4000\XZ` の形にする。`SR500_550_4000` や `XZ` だけを写さない（`SR500_550_4000` を選ぶと親の名が `CASIO` であることを確かめるので〈29 IO-09 の手順 3 `resolve_register_sd_root`〉、「場所を選ぶ」で止まる）。
2. SD に書かない・消さない・名前を変えない（写すだけ）。写し終えた SD はすぐにレジへ戻す。
3. 綴りの紙を 2 日分、紙かそのコピーで店から借りる（写真は撮らない）。比べる日（手順 2・3）の分と、取り消して取り込み直す日（手順 5。以下「手順 5 の日」）の分。この 2 日は、同じ月の、1 回だけ精算した日を店に聞いて選ぶ（使える日かは手順 1 の一覧で確かめる）。その月には、この 2 日のほかに取り込める日が 1 日以上要る（手順 1 で、取り込まずに残す日にする）。日は写しを取った日に近い日にする（古い日ほど早く一覧から落ちる。下の「準備」の 4）。
4. 同じ日に 2 回以上精算した日も並べるなら（手順 8。任意で、合否に数えない）、その日の紙も同じように借りる。
5. 管理者の記録に、写した日と綴りの紙を借りた日を書く。

## 準備（開発用の Windows）

1. 写しを USB メモリから開発用の Windows の置き場（上の「店のデータの置き場と渡し方」）へ、同じ形（`<日付の folder>\CASIO\SR500_550_4000\XZ`）で写す。
2. [msi-distribution-runbook.md](msi-distribution-runbook.md) の「予行演習の準備と片付け」（[確かめる項目](msi-distribution-runbook.md#確かめる項目) の節）の「始める前に」のとおり、開発の data folder（`%APPDATA%` と `%LOCALAPPDATA%` の `com.inventory-system.desktop`）を退避する。開発に使っている data folder（開発の試験のデータ・合成の日報が入ったもの）の上で受入を走らせない（取込み済みの状態と窓が変わり、合否が読めない）。
3. 店へ入れる版の MSI を入れ、最初の起動の前にショートカットの作業フォルダーに `inventory.db` が無いことを確かめてから（同じ節の 2 つ目の段）起動する。商品と日報の取込みが 0 件の空の DB であることを確かめる。`バックアップ・復元` の画面の `バックアップ設定` で、`現在の保存先` に出る場所が受入の data folder（`%APPDATA%\com.inventory-system.desktop`）の中で、その下に `保存先が未設定のためアプリ既定フォルダに保存されます` が出ていることも確かめる（backup が受入の data folder の中にできる）。取込みが 1 件でもあるか、この保存先の表示が違えば止める。
4. 下の手順は、選ぶ日（紙を借りた 2 日、取り込まずに残す日、手順 8 を行うならその日）のうち一番古い日から 30 日以内に走らせる（写しを取った日から数えない。選ぶ日は写しを取った日かそれより前なので、その分だけ期限が早い）。窓は、手順を走らせる日の開発用の Windows の今日から 30 日前まで（37 §37.9 の手順 2）で、それより古い日は一覧に出ない。窓の外に落ちた日は受入で読まない。予備の経路「ファイルを選んで取り込む」（55 UI-07-D16）は受入で使わない。紙を借りた日が窓から落ちたときの扱いは手順 1。
5. 同じ日に初期投入の流れ 2（予行演習）と続けて行うときは、先に行う方の「終わった後」（msi-distribution-runbook.md の同じ節）まで済ませてから、後に行う方の「始める前に」から始める（流れ 2 の後の DB は商品が入っていて空でない）。受入の data folder と流れ 2 の folder は別の名で保全し、混ぜない。

## 手順

取込みと復元は、準備で作った受入の data folder の中だけで行う。値を比べる相手は、どの手順でも借りた綴りの紙だけにする（画面の値を運ばない。上の「店のデータの置き場と渡し方」の渡し方の規則）。月次を紙と比べるのは手順 6 の復元の後の 1 回だけで、紙を借りた 1 回精算の 2 日（比べる日と手順 5 の日）だけを取り込んだ状態で済ませる。2 回以上精算した日を取り込むのは、その後の手順 8。SD の一覧は `日報取込み` の tab を離れると消えるので、戻って取り込む手順（5・6・8）は一覧の読み直しから始める。手順 6 の backup の作成から復元までは同じ日のうちに行う（日をまたぐと起動の時の保持日数の削除で backup が消えうる。71 MNT-01-D3、初期投入の流れ 2 と同じ注意）。

1. **一覧を読み、日を確かめる。** `売上データ取込み` の画面の `日報取込み` の tab で `SD から読む` を押す。SD が見つからないので `場所を選ぶ` が出る。それを押し、写しの `<日付の folder>\CASIO` か `<日付の folder>\CASIO\SR500_550_4000` を選ぶ（後の手順の「一覧を読み直す」も同じ操作）。一覧の日の範囲と件数を管理者の記録に書く（O2 (iii)）。一覧で次の 2 つを確かめる。
   - 紙を借りた 2 日（比べる日と手順 5 の日）が、同じ月の窓の中の `取り込めます` の日で、1 回精算（一覧のその日の行が 1 つ）である。
   - 同じ月の窓の中の `取り込めます` の日から、手順 4 と手順 6 に使う、取り込まずに残す日を 1 日選べる。

   借りた日が一覧に無い（窓の外・`取り込めます` でない状態を含む）、2 回以上の精算、2 日が同じ月でない、残す日が無い、のどれかなら、その月を比べる月にせず、取込みを始めない。次の訪店で写しと紙を取り直す（借りる紙を増やさない）。
2. **比べる日を取り込む。** 一覧の比べる日の行の `確認する` → `取込み内容` を見て `取り込む` → `日報取込み完了` が出る。
3. **綴りの紙と並べる。** `日次売上` の画面を開き、日付の入力と `前日`・`翌日` で比べる日へ着く。`レジ日報（公式）` の `日計（Z001）`・`支払集計（Z002）`・`部門別集計（Z005）` の 3 つの表を、借りた比べる日の綴りの紙（かそのコピー）の同じ帳票の枠と、行ごとに並べる（全部の行の名称・個数/件数・金額。値が 0 の行を含む）。手順 5・6 の「手順 3 と同じ比べ方」は、この並べ方を指す。
4. **取り込んでいない日。** `日次売上` の画面で `前日`・`翌日`・日付の入力で、手順 1 で残した日へ着き、`この日付のレジ日報は未取込みです。` が出ることを見る（手順 6 の後に行ってもよい。復元でその日は未取込みに戻る）。
5. **取り消して取り込み直し、紙と並べる。** `日報取込み` の tab へ戻り、一覧を読み直す。手順 5 の日（手順 1 で確かめた、比べる月のまだ取り込んでいない、紙を借りた日）の行の `確認する` → `取り込む` → `日報取込み完了` の画面のまま `取り消す`（確認の dialog の `取り消す`）→ `日報取込みを取り消しました` が出る → `日次売上` でその日に `この日付のレジ日報は未取込みです。` が出る → `日報取込み` の tab で一覧を読み直し、同じ束（その日の行）を取り込み直す → `日次売上` の画面のその日の 3 つの表を、借りた手順 5 の日の綴りの紙と、枠と行ごとに並べる（手順 3 と同じ比べ方）。取り込み直した日は取込み済みになり、手順 6 の紙の和に入る。手順 4 と手順 6 に使う取り込まずに残す日には触れない。
6. **backup/restore 後の再現と、月次の値。** 取消を使わないので A に依らない。
   1. backup を作る。`バックアップ・復元` の画面の `手動バックアップ` の `今すぐバックアップを作成` を押す。backup は受入の data folder の中だけに作る。受入の間は `バックアップ設定` の `保存先を選ぶ` を押さない（保存先を変えると、受入の data folder の外に backup ができうる）。backup を受入の data folder の外（USB メモリを含む）に作らず、作った backup を受入の data folder から他へ写さない・移さない（上の「店のデータの置き場と渡し方」の「アプリが作る物」）。
   2. 残した日を取り込む。`日報取込み` の tab で一覧を読み直し、手順 1 で残した比べる月の日の束を 1 つ取り込み、`日次売上` でその日の値が変わる（未取込みの note が消えて表が出る）のを見る。
   3. 復元する。`バックアップ・復元` の一覧から、この手順の 1 で作った backup だけを選び、`この控えに戻す` → `復元の確認へ進む` → 確認の dialog で戻す（同じ日のうちに。戻す前の自動の backup は残る、68 §68.4）。
   4. 復元の後、日次・月次の値が backup を作った時の値と同じことを、金額を書かずに次の 3 つで確かめる。
      - 日次の 2 日: `日次売上` の画面で、日付の入力と `前日`・`翌日` で比べる日と手順 5 の日をそれぞれ開き、その日の 3 つの表を、その日の借りた綴りの紙と、枠と行ごとに並べる（手順 3 と同じ比べ方）。
      - 後で取り込んだ日: この手順の 2 で取り込んだ日が `この日付のレジ日報は未取込みです。` に戻る。
      - 月次: `月次` の tab を押して `月次売上` の画面へ移る（tab は日次で開いていた日の月を開くので、比べる月が開く。57 UI-09b-D11）。月を移って着くことを見るため、`前月` で前の月へ移ってから、月の入力か `翌月` で比べる月へ戻る。`公式部門集計（レジ日報由来）` の部門ごとの額が、比べる日と手順 5 の日の借りた綴りの紙の部門別集計の額の和と同じことを見る（後で取り込んだ日の分は入らない）。和は紙から電卓で出し、電卓の結果は紙に控えず、その場で画面の行と比べる。月次を紙の和と比べるのはこの 1 回だけで、この 1 回で 56 UI-09a-D13 の backup/restore 後の再現と 57 UI-09b-D9 の修正後の値の両方を判定する。
   5. 対象日へ戻る。月次の画面から `日次` の tab を押し、日付の入力と `前日`・`翌日` で比べる日へ着くことを見る（57 UI-09b-D9 の過去月・対象日への到達。値はこの手順の 4 で比べ済みで、比べ直さない）。
   6. 取り込んだ日の一覧を見る。この手順の 5 で着いた `日次売上` の比べる日から `月次` の tab を押し、比べる月の `月次売上` が開くことを見る。`公式部門集計（レジ日報由来）` の `取り込んだ日` の見出しの数が `2日分` で、比べる日と手順 5 の日が並ぶ。この手順の 2 で取り込んで復元で戻った日（手順 1 で残した日）は `取り込んでいない日` に並ぶ（今日の日は数えないので、残した日が手順を走らせる日の今日なら並ばない）。`取り込んだ日` の比べる日を押し、`日次売上` のその日が開くことを見る（値は比べ直さない）。
7. **取り込んだ日の無い月。** `月次` の tab で `月次売上` の画面へ戻り、月の入力と `前月`・`翌月` で取り込んだ日の無い月へ移って、`この月のレジ日報は未取込みです。` が出て、`取り込んだ日`・`取り込んでいない日` の見出しと日の一覧が出ないことを見る（`公式部門集計（レジ日報由来）` の見出しの下の説明の文は出て、`取り込んだ日` の語を含む）。数値は比べない（月次の公式部門集計の比べは手順 6 で判定済み）。
8. **2 回以上精算した日（任意。合否に数えない）。** 並べるときだけ、手順 7 までの判定を済ませた後に行う。`日報取込み` の tab で一覧を読み直し、その日の行を 1 つずつ `確認する` → `取り込む`（次の行は完了の画面の `SD の一覧へ戻る` から選ぶ）。2 つめの束では `同じ日の取込みがあります` が出るので、同じ日の別の精算であることを確かめて進む。借りたその日の綴りの紙と、`日次売上` の画面のその日の 3 つの表を、枠と行ごとに並べ、違った行の名称を管理者の記録に控える（金額を書かない。O2 (i)）。この取込みで月次の値が変わりうるので、この後は月次の判定（手順 6）に戻らない。
9. **記録と判定。** 下の合格基準の表の行ごとに PASS/FAIL を管理者の記録に書き、下の「判定」の規則で全体を決める。

## 判定

- 「前提の lane の後に足す」のままの行が残る版、または A・B の lane が merge される前の版では、全体の判定は未了で、初期投入の流れ 3 へ進まない（他の項目が全部 PASS でも）。
- 全体の合格は、「前提の lane の後に足す」のままの行が無く、行う行が全部 PASS のときだけ。月の帳票との照合の行は「行わない（理由）」と書いた間は合否に数えない。
- FAIL の扱い（O5）: 1 つでも FAIL があれば運用を始めない（初期投入の流れ 3 へ進まない）。合わなかった項目と行の名称を控え、直す lane を起こす。直す lane の発注に書くのは項目と行の名称だけにする。金額・写し・受入の data folder・path は渡さず、agent は合成の日報で再現する。店の DB には受入の記録が無いので、店の側で戻す操作は無い。この受入の「終わった後」を済ませてから、直した版で、準備の 1 から受入をやり直す（選ぶ日が窓から落ちていれば〈準備の 4〉、「写しを取る」から。「終わった後」の 3 で返した紙は、「写しを取る」の 3・4 のとおり借り直す）。

## 受入の data folder が壊れたとき

受入の途中で受入の data folder が壊れたら、消さず、他の場所へ移さず、同じ親の中の別名で保全して、準備の 3 の途中からやり直す。写しは USB メモリと開発用の Windows の folder に残っているので、取り直さない。

1. アプリを止め、タスク マネージャーでプロセスが残っていないことを確かめる（msi-distribution-runbook.md の「予行演習の準備と片付け」の「始める前に」と同じ確かめ）。
2. `%APPDATA%\com.inventory-system.desktop` と `%LOCALAPPDATA%\com.inventory-system.desktop` の名前を、それぞれ同じ親（`%APPDATA%`・`%LOCALAPPDATA%`）の中で別名に変える。別名は、準備の 2 で開発の data folder を退避した名と違う、受入の保全と分かる名にし、その名を管理者の記録に控える（終わった後の片付けは、準備の 2 で控えた名の folder を開発の data folder として戻す。名を取り違えると、店のデータの入った folder が開発の data folder になる）。
3. 準備の 2 の「始める前に」は流し直さない（開発の data folder は退避したままで、あったか無かったかの控えを取り直すと、終わった後に開発の data folder を戻す手順を誤る）。
4. 準備の 3 を、「MSI を入れ」を飛ばして行う（MSI は入れ直さない）。最初の起動の前に `inventory.db` が無いことを確かめてから起動し、空の DB と保存先の表示を確かめる。その後、手順 1 からやり直す。

## 終わった後

1. アプリを止め、msi-distribution-runbook.md の「予行演習の準備と片付け」の「終わった後」の順で開発の data folder を戻す。その手順の (2) で、受入の data folder（`%APPDATA%\com.inventory-system.desktop`。取り込んだ記録・SD の写し〈IO-10〉・backup を持つ）と WebView の保存の `%LOCALAPPDATA%\com.inventory-system.desktop` は消さずに別名で残る。(2) で付ける別名は、準備の 2 で控えた退避の名と違う、受入の保全と分かる名にし、その名を管理者の記録に控える（名を取り違えると、その手順の (4) で、店のデータの入った folder が開発の data folder として戻る）。
2. この 2 つの別名の folder、受入の data folder が壊れたときに保全した別名の folder（上の「受入の data folder が壊れたとき」の 2。あれば）、USB メモリの写し、開発用の Windows の写しは店のデータで、FAIL の直しの再受入まで保ち、消す時期は owner が決める（71 §71.13 の別の PC に店のデータを置く間の扱いと同じ。開発用の Windows へ写して確かめた後に USB メモリの写しを残すかも、この判断に含める）。
